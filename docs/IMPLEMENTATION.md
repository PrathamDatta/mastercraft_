# Implementation report — Mastercraft Engineers redesign

Audit date: 2026-10-27. Everything below was done in this working copy; **nothing was deployed** and the production site was not modified.

## 1. Audit of the existing site

**Stack:** WordPress 5.2.21 (end-of-life) + WPBakery Page Builder + Slider Revolution 5.4.7.2, theme markup left over from a LearnDash course theme (an unused "Search Courses" form is in every page). No repository was supplied, so this is a separate implementation.

**Pages found (7):** `/`, `/facilities/`, `/components/`, `/injection-moulds/`, `/2k-parts/`, `/large-size-injection-moulds/`, `/contact/`.

**Strengths:** genuinely good, authentic photography (machining, CMM, MFI tester, moulding hall, mould/part pairs); real, specific technical data (17 large moulds, 7 small moulds, 18 components, 4 2K parts, machine strokes, clamping range); clean URL structure; a corporate YouTube video.

**Problems:** no meta descriptions; no XML sitemap (`/sitemap.xml` 404); robots.txt only disallows `wp-admin`; empty `alt` text on images; `href="#"` menu parents; home page has almost no copy; a hero "slider" with a placeholder image; "enter any two digits" spam field in the form; unoptimised JPEGs, no responsive images or modern formats; external Google Font and render-blocking WP/WPBakery assets; end-of-life CMS; no structured data; no "About", "Quality" or product-detail pages although the content existed.

**Content oddities to confirm with the client** (kept exactly as published, not "corrected"):
- *Housing Drive* mould: **4 t** for a 396 × 396 × 385 mm mould looks too heavy relative to the other moulds (possibly 0.4 t).
- 3-axis stroke is published as "**900 mm to 700 mm**"; the envelope diagram draws it as 900 × 700 mm and says so.
- Facilities states moulded parts of **0.5 ~ 300 g**, yet the components page lists a **0.11 g** clip frame.
- *Centre tube* group lists three parts but only two materials; the top cap shows no material.
- Several part names include the word "Hyundai" (*Cover/Housing Drive Hyundai*). The site does not claim any customer relationship and neither does the redesign; the word appears only inside the original part name. Decide whether to keep it.
- "SVG" in hot-runner entries is kept as written (not expanded).

## 2. Architecture decision
A **dependency-free static site** generated by a small Node build (`src/`), deployed as plain files, with one serverless function (`api/contact.js`) for the form. It was first written for the existing PHP/WordPress host and then moved to Vercel when the owner chose Vercel hosting. Rationale: content is small and stable; static output gives the best Core Web Vitals and eliminates the end-of-life WordPress attack surface; all URLs are preserved; no framework migration was needed. Motion uses CSS + ~9 KB (3 KB gzipped) of vanilla JS — no GSAP/Motion/Three.js, because nothing here needed them (no WebGL, so there is no WebGL failure path; the hero is a photograph with CSS/SVG layers).

> **This branch (`variant-b-light`) carries Variant B, "Daylight". Sections 3 and 9 describe Variant A, "Forge" (branch `main`); Variant B is described in section 10.** Content, SEO, GEO, accessibility, form, redirects and tests are identical in both.

## 3. Design system ("Forge", v2)
The first design (logo-derived orange on beige/near-black, condensed type) was replaced at the owner's request with a bolder, more "glam" one that **keeps the original site's colour scheme**: brand orange `#e1883e` (hover `#cc6e20`), black `#000` and white `#fff`, taken from the old site's `color-scheme.css`. Small neutral greys are derived for surfaces; a darker orange (`#a64c0b`) is used for small orange *text* on white so it meets contrast.
- **Type:** Archivo variable at its widest (expanded, heavy, uppercase) for display; Instrument Serif italic for accent words in orange; IBM Plex Mono for technical labels. All self-hosted woff2.
- **Surfaces:** alternating stark black / white sections with diagonal cuts, film grain on black, orange glow orbs, pill buttons with a light sweep, 28 px rounded cards.
- **Effects (all vanilla CSS/JS, no libraries):** hero photo that turns from monochrome to full colour under a spotlight that follows the mouse (drifts on its own on touch); per-letter 3D headline entrance with a shimmering serif accent; floating spec chips with pointer parallax; rotating logo-mark badge; capability marquee; count-up stat numerals (final values are in the HTML); a **stacked sticky process deck** where cards pile up, shrink and dim, then release; draggable product rail with arrow buttons and progress bar; 3D tilt cards with moving glare; magnetic CTA buttons; cursor ring with "View" labels (mouse only; native cursor stays); scroll progress bar; header that tucks away on scroll-down; scroll-linked kinetic tagline; orange-curtain image reveals and scan-line highlights; outlined year that fills with orange; giant footer wordmark that fills on hover; cross-document view transitions.
- **Restraint:** one scroll listener and one rAF per frame; looping animations pause when off-screen; the hero loop runs only while visible; transform/opacity/clip-path only.
- **Accessibility of the effects:** everything is disabled or made static under `prefers-reduced-motion` (tested); pointer effects only for a real mouse; the animated hero headline carries its full text as the accessible name; decorative layers are `aria-hidden`; sticky stacking is desktop-only and the deck is a plain list on mobile or without JS; the rail is a keyboard-focusable region with real buttons.

## 4. What was built
- **Pages (48 incl. 404/thank-you):** Home, About (new — company facts, vision, video facade), Facilities, Quality (new — CMM/MFI/SPC, glossary), four product listings, **37 product-detail pages generated from one template** (`detailPage`), Contact, Thank-you (noindex), 404.
- **Home:** hero with annotated real machining photo and tool-measurement inset → company story with design→mould→component strip → **stacked 7-card manufacturing deck** (project management, CAD, CAM, machining, assembly, injection moulding, inspection; machining, moulding and inspection carry an "Inspection point" tag) → product showcase → quality → FAQ → enquiry CTA. Only stages supported by the old site are shown; "delivery" appears as a commitment in stage 1 because the old site gives no separate delivery stage.
- **Infographics (all SVG/CSS/HTML, keyboard accessible, with text equivalents):** process deck; **mould anatomy** — real mould photo with 4 hotspots, labelling only what is visible; **machining envelopes drawn to scale** from published strokes with legend and table; **range rulers** for 45–150 t clamping and 0.5–300 g parts; **large-mould weight chart** (17 moulds, each bar a link) and full spec index table; materials list.
- **Navigation:** sticky, dropdown for Products implemented as link + disclosure button (works by click/keyboard/touch, not hover-only), `aria-current`, accessible full-screen mobile menu with focus trap/Escape, prominent "Discuss your project" CTA. The unused search form was dropped.
- **Contact:** labelled, validated form (client + server), inline errors with `aria-describedby`, live status region, honeypot + time trap instead of the digits field, prefill from product pages (`?ref=`), no-JS native POST fallback; address, both phone numbers, e-mail and a Maps *link* (no heavy map embed).

## 5. SEO / GEO / local
- Unique title + description + canonical per page, single H1, ordered headings; images have descriptive filenames, alt text, intrinsic dimensions, AVIF/WebP/JPEG `<picture>` with responsive `srcset`, lazy loading except the hero (preloaded, `fetchpriority=high`).
- `sitemap.xml` (46 URLs with image entries), `robots.txt`, `404.html`, noindex on the thank-you page, `www`→apex redirect and legacy WordPress image 301s in `vercel.json` (HTTPS is enforced by Vercel). All 7 old page URLs are unchanged.
- JSON-LD (parse-checked): `Organization`+`LocalBusiness` (verified name, address, two phones, e-mail, founding year 1992, logo, YouTube `sameAs`; **no** invented geo, hours, ratings, prices or reviews), `WebSite`, `WebPage`/`AboutPage`/`ContactPage`/`CollectionPage`, `ItemList` on listings, `BreadcrumbList`, `Product` on detail pages (specs as `additionalProperty`, no offers/price), `FAQPage` on the home page (matches visible text).
- **No `VideoObject`:** schema requires an upload date, which could not be verified (YouTube did not expose it). Add it once the date is confirmed.
- **GEO:** consistent entity facts everywhere (footer, About "at a glance" table, Contact, JSON-LD); concise factual copy; spec tables in crawlable HTML; FAQ answering real procurement questions only from published data; glossary (HRS, CMM, MFI, SPC, EDM, 2K); contextual internal links; no fabricated certifications, customers, testimonials or statistics (every number on the site is either quoted from the old site or computed from it, e.g. "17 moulds", "1.3 – 18.5 t").
- **`llms.txt` not added.** A search on 2026-10-27 found no confirmation from Google or OpenAI that they read it, and sources disagreed; it adds maintenance with no verified benefit. Revisit if a major provider documents support. No special AI-crawler directives were added either.
- **Keywords:** the brief's phrases and the site's own wording were used naturally (precision injection mould, Bengaluru/Bangalore, large injection moulds, plastic injection-moulded components, 2K parts, CMM/MFI/SPC). **No keyword-research tool was available, so demand and competitiveness are unverified.** No location-landing pages were created.
- Security/privacy: CSP via `<meta>`, YouTube loaded only on click from `youtube-nocookie.com`, no analytics/third-party scripts (the old site had none visible in its HTML; add consent-aware analytics if needed).

## 6. Tests executed and actual results
Run with `npm test` (build → static checks → browser tests). Final run after all fixes:

| Check | Result |
|---|---|
| Build | 48 pages, sitemap 46 URLs |
| Static checks (`scripts/check.mjs`) | **PASS** — 48 pages, ~1,780 internal links, 351 `<img>`: unique titles/descriptions, canonicals, one H1, no heading jumps, valid JSON-LD, no broken links/anchors/images, no duplicate ids, no orphans, sitemap matches pages. Warnings only for the two noindex utility pages' short descriptions |
| Browser tests (`scripts/e2e.mjs`) | **640 / 640 passed** — every page at 375 / 820 / 1440 px: status, no console errors/warnings, no horizontal overflow, no broken images; **axe-core WCAG 2.0–2.2 A/AA + best-practices: 0 violations** on 11 representative pages at desktop and mobile; mobile menu, Escape/focus return, dropdown by keyboard, hero spotlight following the pointer, sticky deck stacking/sinking and releasing, header hide/show, progress bar, rail buttons, counters ending on the published values, hotspot toggling, form validation/success/server validation/header-injection/honeypot/cross-origin rejection/GET 405, reduced motion, no-JS rendering, video not loaded until requested, trailing-slash redirect |
| Lighthouse (headless Chromium, simulated mobile throttling, gzip like production) — **redesign v2** | Mobile: Performance **97–99**, Accessibility **100**, Best Practices **100**, SEO **100**; **LCP 2.1–2.4 s, CLS 0, TBT ≤ 40 ms** (home 2.4 s, listing/facilities 2.1 s, detail 2.3 s); page weight 177–275 KiB. Desktop home: 100 / 100 / 100 / 100, LCP 0.5 s |

Notes on these numbers: they are **lab results from a local server**, not field data; **INP cannot be measured in the lab** (TBT 0 ms is a proxy) and must be checked in Search Console/CrUX after launch. Without gzip (PHP's dev server) the same mobile home page scored 95 with LCP 2.7–2.8 s because of simulated slow-network transfer of the 42 KB uncompressed CSS (9.6 KB gzipped) — Vercel compresses responses automatically.

Issues found and fixed during testing: pre-reveal image scale caused horizontal overflow on narrow screens; reveal clip-path on the observed element stopped IntersectionObserver from firing; colour contrast on dimmed process steps; redundant alt text in the gallery; an error message appearing on field blur shifted the Submit button so the click was lost (real bug — fixed); the same-origin check in the original PHP handler mishandled non-default ports (the handler has since been rewritten as `api/contact.js` for Vercel and re-tested).

## 7. Not done / limitations / assumptions
- **Not deployed.** See `DEPLOY.md`. Email delivery from `/api/contact` was tested only in dry-run (it logs instead of sending) and the Resend call was never executed, because no API key exists; verify real delivery on a Vercel preview after setting the environment variables and verifying the sending domain.
- Third-party validators (Google Rich Results Test, Schema.org validator, WebPageTest, real-device testing, Safari/Firefox) were not run. Playwright tested Chromium only.
- No new photography or video was created. The hero uses the existing machining photo; the callouts name only visible features. Original images are mostly ≤1.5k px wide and a few are soft; the campus aerial is a video still. **Recommended new assets:** a high-resolution hero video or photo set of the machining floor, a mould-opening or CMM clip, and a transcript for the corporate video.
- Photo-derived captions (e.g. "Tool measurement", "Coolant delivery") are descriptive of what is visible; the owner should confirm the machine/equipment identities.
- The Google Business Profile, citations and other off-site entity signals are external actions not performed.
- Product detail pages are generated from the same published data as the listings (they add structure, cross-links and schema, not new facts). If Mastercraft prefers not to have 38 near-template pages indexed, set `noindex` in `detailPage` or drop them from the sitemap.
- The brand wordmark PNG is low resolution (666 px wide); an SVG logo from the client would be sharper.

## 9. Redesign v2 notes (branch `glam-redesign`)
Re-verified on the redesigned build: static checks PASS, **640/640** browser tests (incl. axe 0 violations on 11 pages × 2 widths), Lighthouse as above. Issues found by the tests during the redesign and fixed: 4-column stats band overflowed at 1440 px (now 2×2); long uppercase heading words overflowed narrow columns (word-break safety net + earlier stacking); sections using a renamed class lost their black background (caught by axe); a tab-through of the header while it is tucked away is covered by `:focus-within`.
Known trade-offs of the "glam" direction: more motion and a heavier visual language than the first design; the cursor ring, tilt, magnetic buttons and spotlight need a mouse; `backdrop-filter` on the header is skipped by older browsers (falls back to a solid dark bar). Effects were checked in Chromium only.

## 10. Variant B "Daylight" (branch `variant-b-light`)
A second, structurally different design for client comparison. Same content, URLs, copy, data, SEO/structured data and form as Variant A; only the visual system and the page structure differ.
- **Palette:** the logo's orange `#f18325` and white, with soft orange tints (`#fff7f0`, `#ffebdb`, `#ffd9b8`) and a warm near-black for text. Buttons use orange with dark text (white on this orange would fail contrast); small orange text on white uses a darker orange (`#a85208`).
- **Type:** Bricolage Grotesque (display) and Figtree (text), both self-hosted variable fonts (~61 KB together). Sentence case, friendly and rounded.
- **Structure:** floating pill header; hero collage (arch-cropped machining photo, two overlapping photos, floating spec chips, rotating badge, morphing orange shape, brush underline drawn under "mould engineering"); **bento grid** replacing the marquee/stats (injection moulding, machining, quality photo tiles; large and small mould counts with count-up numerals); company story with offset orange frame; **zig-zag process timeline** whose orange line draws as you scroll and whose stages light up; **tabbed product explorer** (accessible tabs with arrow/Home/End keys; all four panels are shown if JavaScript is off); quality section with arch-cropped photos; accordion FAQ; orange "sheet" CTA with a ghost logo mark; light footer. Inner pages use a tinted rounded header band, white spec cards and an orange highlight tile row on product pages.
- **Motion:** gentler than Variant A: staggered rise-in, image reveals, float loops (paused when off-screen), timeline drawing, count-ups, card lifts and shine sweeps on buttons. Everything is disabled or static under `prefers-reduced-motion` (tested).
- **Results (same checks as Variant A):** static checks PASS; **640/640** browser tests (axe 0 violations on 11 pages × 2 widths, no overflow at 375/820/1440 px, keyboard, form, reduced motion, no-JS); Lighthouse (headless Chromium, simulated mobile throttling, gzip): Performance **97–100**, Accessibility/Best Practices/SEO **100**; **LCP 1.5–1.9 s, CLS 0, TBT ≤ 30 ms**; page weight 93–220 KiB.
- **Choosing:** both variants can be previewed at once on Vercel (each branch gets its own preview URL). Merging the chosen branch into `main` publishes it. See `docs/DEPLOY.md`.
