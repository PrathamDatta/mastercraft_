# Deployment checklist — Vercel

**Nothing has been deployed** and the production DNS/site was not touched. Go-live needs the owner's authorisation and access to the domain registrar/DNS.

## What changed for Vercel
- `vercel.json` (generated by `npm run build`, committed) sets: build command, `dist/` output, trailing slashes, security headers (incl. HSTS), long-cache headers for images/fonts, `www → apex` redirect, and 301s from the old WordPress image URLs (`/wp/wp-content/uploads/…`) to the new optimised images.
- The enquiry form posts to **`/api/contact`** (`api/contact.js`, a Vercel Node serverless function) instead of PHP. It validates server-side, checks same-origin, uses a honeypot + time trap and sends the mail through the **Resend** HTTP API.
- Old PHP/`.htaccess` files were removed. All seven original page URLs are unchanged, so no page redirects are needed.

## One-time setup
1. In Vercel: **Add New → Project → import `PrathamDatta/mastercraft_`**. Framework preset: *Other*. Build/Output settings are read from `vercel.json` (Node 20+; `npm install` also installs the build tools `sharp` and `esbuild`).
2. **Email (required for the form to work).** Create a Resend account, add and verify the sending domain `mastercraftengineers.com` (SPF/DKIM records at the DNS host), create an API key, then set these in *Project → Settings → Environment Variables* (Production + Preview):

   | Variable | Value |
   |---|---|
   | `RESEND_API_KEY` | key from Resend (secret — never commit it) |
   | `CONTACT_FROM` | e.g. `Mastercraft Website <website@mastercraftengineers.com>` (must be on the verified domain) |
   | `CONTACT_TO` | optional; defaults to `info@mcraft.net` |

   Without these the form shows a friendly fallback ("email info@mcraft.net or call …") and logs an error. Any other transactional email provider can be swapped in inside `api/contact.js` (one `fetch` call).
3. The first build runs the image pipeline (AVIF/WebP for ~50 photos). Expect a few minutes; later builds are the same because Vercel does not keep `.cache`. If build time ever becomes a concern, commit the generated `dist/assets/img` or move to a cached build step.

## Preview first
Every push to a branch gets a preview URL. Test there: pages, the form (send a real enquiry; confirm it arrives at `CONTACT_TO` and that Reply-To is the visitor), `/robots.txt`, `/sitemap.xml`, a made-up URL (styled 404 with HTTP 404), old image URL redirect, e.g. `/wp/wp-content/uploads/2019/10/machining5.jpg`. Previews are not indexed by default (Vercel adds `X-Robots-Tag: noindex` to `*.vercel.app` previews).

## Go-live
1. Merge the branch to `main` (production branch). 
2. *Project → Settings → Domains*: add `mastercraftengineers.com` (primary) and `www.mastercraftengineers.com`. Follow Vercel's DNS instructions (A record for the apex, CNAME for `www`) at the registrar. Keep the **old WordPress host running until DNS has propagated and the new site is verified**; lower the DNS TTL beforehand.
3. HTTPS certificates are issued automatically. `www` redirects to the apex via `vercel.json`.
4. Email: keep any existing MX/mail records for `@mcraft.net` / the domain untouched — moving the website does not move mail. Do **not** change MX records when pointing the web DNS at Vercel.

## After go-live
- Verify the property in **Google Search Console** and Bing Webmaster Tools, submit `https://mastercraftengineers.com/sitemap.xml`, inspect `/` and a product page. Field Core Web Vitals (incl. INP) appear after ~28 days.
- Run Google's **Rich Results Test** and the Schema.org validator on `/`, a listing and a product page (JSON-LD was parse-checked locally only).
- Claim/verify the **Google Business Profile** with the same address and phone numbers as the site (external action, not done).
- Re-run Lighthouse on the live URL and compare with `IMPLEMENTATION.md`. Vercel serves gzip/brotli and HTTP/2+, so results should match or beat the local gzip numbers.
- Decommission the old WordPress site, plugins and database (unpatched WordPress 5.2 is a security risk) once satisfied.
- Optional: add Vercel Web Analytics / Speed Insights (no code change needed beyond enabling them; CSP would need a matching `script-src` entry — review before enabling).

## Rollback
Vercel keeps every deployment: *Deployments → ⋯ → Promote to Production* on a previous build, or revert the merge. DNS can be pointed back at the old WordPress host. No database is involved.

## Local equivalents
`npm run build` → `npm run serve` (http://127.0.0.1:8080 — static files + `/api/contact` in dry-run mode, mail goes to a temp log) → `npm test`.
